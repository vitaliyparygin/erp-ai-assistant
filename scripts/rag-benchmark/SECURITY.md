# Security Policy

## Supported Versions

The latest released version is actively maintained.

Older releases may receive security fixes at the maintainer's discretion.

## Reporting a Security Vulnerability

Please do **not** open a public GitHub issue for security vulnerabilities.

Instead:

* Contact the maintainer privately.
* Include a clear description of the issue.
* Provide reproduction steps if possible.
* Include affected versions.
* Include potential impact.

A response will typically be provided within a few days.

## Responsible Disclosure

Please allow reasonable time for a fix before publicly disclosing a vulnerability.

## Scope

Security reports may include issues such as:

* Arbitrary code execution
* Path traversal
* Unsafe file handling
* Template loading vulnerabilities
* Dependency vulnerabilities
* Command injection
* Unsafe deserialization

General bugs, feature requests, and usability improvements should be reported through the GitHub Issues page.
